### The 1 failure — not a regression, working as documented

`p7_detection::defect_required_input_no_default_blind_spot` fails when forced
to run under `--include-ignored`. This is **by design**: it's an `#[ignore]`d
test that documents a known, permanently-open harness blind spot ("required
input with no default" cannot be flagged without false-positiving on
legitimate cog-arch workflows that declare required operator inputs — the doc
comment in `p7_detection.rs` calls it "UNCLOSEABLE without false positives").
The test body asserts `has_failures()` is true and panics because it's false —
that's the test *demonstrating* the gap it documents. It is not new, not
touched by the change-atom migration, and not a regression. Every other test —
including the ones marked `#[ignore]` for being slow — passed.

ignored test (`crates/praxec-test/tests/zz_session_migration_fuzz.rs`, not

## 3. Findings outside the 7 target flows (informational, not a blocker)

The combined config (both pack repos) has 134 definitions / 823 edges total.
Running the same `fuzz_coverage` pass over the *whole* combined pack (not just
the 7 targets) surfaced 43 failing edges across 7 *other*, unrelated flows —
all pre-existing, none touched by the change-atom migration:

- `cognitive/cap.gate.human-disambiguate` — 1 edge, `CHOICE_MISMATCH` (a
  human-choice-selection gate the isolated harness can't drive).
- `cognitive/flow.qa.promote-finding` — 46 edges, several
  `GUARD_UNSET_SLOT`/`cap_output_schema_violation` (a fan-out-over-flake-report
  pattern; the same class of "single-state probe can't seed a multi-item
  iteration" gap documented in `p7_detection.rs`).
- `cognitive/cap.implement.regression-test`, `cognitive/cap.implement.fix-under-scope`
  — 1 edge each, `INPUT_SCHEMA_VIOLATION` (dummy-arg generation gap on their
  input schema shape).
- `cognitive/flow.behavioral-coverage` — 2 edges, "could not satisfy guard
  (evidence/role?)".
- `cognitive-max/flow.ux.optimize` — ~19 edges, `GUARD_UNSET_SLOT` on
  `$.context.next_cell.principle` (same multi-item-iteration harness gap as
  `flow.qa.promote-finding`, applied to its own cell-grid fan-out).
- `cognitive/flow.review.docs-fmeca` — 7 edges, `GUARD_UNSET_SLOT` on
  `$.context.current_item.kind` (same class again).

No orphan states, no deterministic loops, anywhere in the 134-definition
combined pack. These are all documented-class harness limitations (multi-item
fan-out / single-edge dummy-arg gaps), pre-date this session's work, and don't
touch any of the 7 migrated flows. Flagging for completeness per the honesty
bar, not as a v0.0.41 blocker.
